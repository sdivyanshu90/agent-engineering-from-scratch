# Competency framework

Mastery concerns demonstrated ability, not attendance or a passing example.

| Level | Evidence | Insufficient substitute |
|---|---|---|
| 1: Explain | Explain mechanism and limitations in your own words | Repeat a definition |
| 2: Trace | Predict state/output for unseen input, then verify | Read a displayed trace |
| 3: Implement | Build from a contract without reference code | Copy and run the solution |
| 4: Debug/adapt | Reproduce a fault, locate cause, fix and regress it | Random edits until green |
| 5: Judge | Compare alternatives using measurements, correctness and risk | Prefer a fashionable tool |

Week 1 requires Level 3 daily and a debugging demonstration by Day 6. Later
planned weeks target Level 4 for reliability and Level 5 for the capstone defense.
These are curriculum goals, not job titles. The manifest records the required
level for each scheduled lesson; authored lessons specify objective evidence.

Daily exams have five points: conceptual, trace/algorithm, independent coding,
debugging, and design reasoning. Award a point only if the answer satisfies the
corresponding reference criteria. Require at least four points and the coding
point. Keep a written evidence trail; self-grading without an independent attempt
cannot justify a skip. Weekly grading is more granular and includes integration.

Reference correctness and learner competence are separate records. Repository
tests validate software behavior. Learner records must include explanations,
unseen examples, and delayed reconstruction. Neither proves years of operational
judgment. The final benchmark and held-out protocol are planned deliverables;
no stochastic model-evaluation results have been obtained.
